## Метрики и границы точности

После каждого API-вызова карточка показывает:

- **Current message ≈** — локальная грубая оценка только новой user-реплики:
  `ceil(utf8.encode(userText).length / 4)`. Это не tokenizer DeepSeek. Для
  коротких чисел, повторов, кода и emoji погрешность может быть большой.
- **Context (API)** — фактический `usage.prompt_tokens`: system prompt из
  `AgentConfig` + вся предыдущая история + новая user-реплика, включая
  служебное оформление сообщений моделью. Последняя реплика уже включена,
  поэтому прибавлять Current message к Context нельзя.
- **Response (API)** — `usage.completion_tokens`.
- **Total call (API)** — `usage.total_tokens`.
- Время получения полного ответа; при ошибке — время до ошибки.

Предварительный context не оценивается. При отклонении запроса usage не
придумывается: стоят прочерки, а точный размер из сообщения провайдера виден
в ошибке. Накопительный счётчик не добавлен: текущий Context не выдаётся за
суммарный расход за жизнь чата. Метрики доступны для вызовов текущего запуска;
восстановленные из Day 7 сообщения не получают выдуманных usage-значений.
Метрики не добавляются в LLM history.

Источник истины для usage — ответ API. DeepSeek также предупреждает, что
приблизительный подсчёт не заменяет usage:
[Token & Token Usage](https://api-docs.deepseek.com/quick_start/token_usage/).

## Agent, persistence и очистка

- Agent по-прежнему владеет `_messages`, сохраняет user до HTTP, assistant
  после успешного ответа и отправляет весь контекст. JSON Day 7 не изменён:
  массив `{role, content}` в Application Support/conversation.json.
- Новая кнопка корзины вызывает `Agent.clearConversation()`: сначала атомарно
  сохраняется пустой массив, затем очищается память. Если запись не удалась,
  старый контекст остаётся. Очистка — явное действие пользователя.
- Отправка, очистка и подготовка demo взаимно исключены. Повтор последнего
  неотвеченного сообщения не дублирует user в контексте.
- При HTTP-ошибке показывается status и ограниченное по длине
  `error.message`. Ключ редактируется, headers и полный response не логируются.
  История не обрезается, ошибка не превращается в ответ assistant.
- `.env` остаётся ignored; API key поступает прежним способом. Новых
  зависимостей, провайдера, ключей или сервера не требуется.

## Быстрая подготовка длинной истории

В debug-сборке меню **⋯ / Day 8 demo** содержит две локальные команды:

1. **Demo: + длинная история** — добавляет user-блок с 4000 повторениями ` x`.
2. **Demo: + overflow (1M+)** — добавляет user-блок с 1 100 000 повторениями ` x`.

Это синтетические данные, а не якобы состоявшиеся ответы модели. Обе команды
добавляют и сохраняют данные, но сами не вызывают API. После них отправьте
короткий вопрос. Полный блок попадёт в следующий реальный HTTP-запрос.
Можно нажать длинную историю несколько раз, наблюдая рост input.

Для отзывчивости UI в длинной реплике видны первые 600 символов и пояснение.
В storage и API текст остаётся полным. В release-сборке demo-меню скрыто.

Текущая модель — **deepseek-v4-flash**, окно **1M**, по фактической ошибке
API — **1 048 576 токенов**. [Документация моделей](https://api-docs.deepseek.com/quick_start/pricing/)
проверена 09.09.2026. `max_tokens` остался 1600 во всех сценариях. Для overflow
сам input уже больше окна: увеличивать лимит вывода или вводить собственный
лимит приложения не потребовалось. Большой блок строится локально за один шаг,
без генерации длинных ответов моделью. Реальный отказ получен примерно за 3 с.
Usage для отказа отсутствует; нулевая стоимость такого запроса не утверждается.

# AI Advent — Day 7 · Сохранение контекста

Запуск остался прежним:

```sh
flutter run --dart-define-from-file=.env
```

Историей и запросами владеет `Agent`; UI читает только `agent.turns`.
Небольшой `HistoryStorage` (`lib/history_storage.dart`) сохраняет JSON через
`dart:io`. Единственная прямая новая зависимость — стандартный Flutter-плагин
[path_provider](https://pub.dev/packages/path_provider), который выбирает
локальную директорию Application Support приложения.

Файл: `<getApplicationSupportDirectory()>/conversation.json`.
На iOS это `Library/Application Support/conversation.json` внутри sandbox
приложения; UUID контейнера может меняться при установке сборки.

```json
[
  {"role": "user", "content": "Сообщение пользователя"},
  {"role": "assistant", "content": "Ответ модели"}
]
```

Порядок задаётся положением в массиве. API key, system prompt, настройки и
метрики запроса не сохраняются в истории. `.env` остаётся ignored, механизм
`String.fromEnvironment` не изменён.

- `Agent.initialize()` один раз загружает и проверяет весь JSON, восстанавливает
  приватный `_messages` и проекцию `turns` для UI. Ввод до завершения отключён;
  сам `send()` также дожидается инициализации.
- User добавляется и сохраняется **до** HTTP-запроса; assistant — сразу после
  ответа. Записи последовательны, одновременные `send` отклоняются.
- Каждый снимок пишется в `conversation.json.tmp` с `flush: true`, затем
  переименовывается в основной файл. Событие закрытия приложения не нужно.
- HTTP body собирает сам Agent: system prompt из `AgentConfig` + `_messages`,
  где уже находятся восстановленная история и новый user. UI не формирует
  контекст. CLI Day 5 по-прежнему создаёт отдельные Agent без storage.
- Нет файла — пустой диалог. Повреждённый JSON или ошибка чтения — пустой
  диалог с понятным предупреждением, без падения. Следующая успешная запись
  заменяет некорректные данные. Сложная recovery-система не добавлена.
- При ошибке записи user запрос не отправляется; при ошибке записи assistant
  ответ остаётся в памяти и показывается предупреждение. Следующая успешная
  запись сохраняет весь текущий список.
- Незавершённый user восстанавливается тоже. Повтор точно такого же последнего
  сообщения без ответа не добавляет дубль. Завершённые одинаковые реплики
  считаются самостоятельными сообщениями.

# AI Advent — Day 6 · Первый агент

Основной экран — чат с независимым stateful `Agent`.

```sh
flutter run --dart-define-from-file=.env
```

Существующий `.env` остаётся ignored. Ключ читает Agent через
`String.fromEnvironment`; UI ключ не получает. Новых зависимостей нет.

## Архитектура

`UI → Agent.send(text) → DeepSeek API → Agent → UI`

- `lib/agent.dart`: `Agent`, неизменяемый `AgentConfig`, готовый `ApiResult`
  и `AgentTurn` для отображения завершённого обмена.
- Agent формирует JSON, вызывает существующий DeepSeek endpoint, обрабатывает
  HTTP/сетевые ошибки и тайм-аут 120 секунд, разбирает ответ и usage,
  измеряет время и рассчитывает стоимость по сохранённым тарифам Day 5.
- Приватный `_messages` принадлежит экземпляру Agent и живёт только в памяти.
  После успешного ответа добавляется пара user/assistant. Следующий запрос
  включает system prompt, весь `_messages` и новое сообщение пользователя.
  Ошибки не добавляются в контекст; повторная отправка не дублирует сообщение.
  Одновременный `send` на том же агенте возвращает понятную ошибку.
- `AgentConfig`: модель (включая ставки для оценки стоимости), system prompt,
  temperature, maxTokens, topP, frequencyPenalty, presencePenalty.
  Конфигурация неизменяема; разные `Agent(configA)` и `Agent(configB)` имеют
  независимые списки истории, даже если используют один config.
- `lib/main.dart`: ввод, состояние ожидания, вывод ошибки, готовых реплик и
  метрик, прокрутка. UI читает неизменяемый снимок `agent.turns`; не хранит
  свой список сообщений, не знает API JSON/ролей/endpoint и не собирает контекст.
- История исчезает при уничтожении агента или перезапуске приложения.
  Database, файлы истории, backend и отдельная сущность Chat не добавлены.
- CLI Day 5 сохранён: `experiment.dart` делегирует запрос новому Agent.

# AI Advent — Day 5 · DeepSeek

Один общий prompt, три реальные модели DeepSeek, одна кнопка запуска.
Нужен только существующий `DEEPSEEK_API_KEY` в локальном `.env`.
Новых ключей и аккаунтов не требуется. `.env` остаётся ignored; секреты не выводятся.

```sh
flutter run --dart-define-from-file=.env
```

После изменения `.env` нужен полный перезапуск. Конфигурация VS Code использует тот же механизм.
Приложение предназначено для личной локальной демонстрации: `dart-define` не является хранилищем секретов в распространяемой сборке.

## Модели и ограничение эксперимента

| Категория в UI | API model | Основание |
|---|---|---|
| Weak · Flash | `deepseek-v4-flash` | Более дешёвая базовая версия относительно Pro |
| Experimental · Vision | `deepseek-v4-flash-vision-exp` | Отдельная экспериментальная версия Flash с поддержкой изображений; здесь получает только текст |
| Strong · Pro | `deepseek-v4-pro` | Более высокий уровень линейки и тариф относительно Flash |

`GET /models` с текущим ключом 06.09.2026 вернул именно эти три ID.
Vision нельзя обоснованно объявить Medium: это не подтверждённый промежуточный уровень.
Таким образом, реализовано сравнение трёх разных моделей **только DeepSeek**, но строгая градация Weak / Medium / Strong не выполнена. Эта граница явно показана в UI.
Категории не являются оценками реальных ответов.

Источники: [модели и цены](https://api-docs.deepseek.com/quick_start/pricing/),
[список моделей](https://api-docs.deepseek.com/api/list-models/),
[режим thinking](https://api-docs.deepseek.com/guides/thinking_mode/).
По документации версии — Flash-0731, Pro-0813 и Flash-Vision-Exp. API ID не фиксируют snapshot, поэтому будущие запуски могут отличаться.

## Общий prompt

Полный user prompt и system prompt находятся в `lib/experiment.dart` и доступны в UI.
Задание: три коробки с монетами ЗЗ, СС и ЗС. Коробку и монету в ней выбирают равновероятно. Увидев золотую монету, нужно найти вероятность того, что оставшаяся тоже золотая, и объяснить, почему это не 1/2. Ответ до 100 слов.

Эталон: **2/3**. Из трёх равновероятных золотых монет две принадлежат коробке ЗЗ. После наблюдения золотой монеты коробка ЗЗ вдвое вероятнее ЗС. Эталон приведён только в документации и не отправляется API. Внизу UI расположен сравнительный анализ времени, input/output/total tokens, стоимости и статуса. После завершения запуска он показывает минимумы среди полных ответов с известными метриками; при равенстве перечисляет все модели. Ошибки, обрезанные ответы и ответы другой модели исключены из минимумов. Качество автоматически не оценивается.

Новый prompt ещё не запускался: по просьбе пользователя после замены задания приложение, API-запросы и проверки не запускались.

Для всех запросов используется один `requestBody`; меняется только `model`:

- одинаковые system и user messages, без истории;
- `temperature: 0`, `top_p: 1`, `max_tokens: 1600`;
- `frequency_penalty: 0`, `presence_penalty: 0`, `n: 1`;
- `stream: false`, `response_format: {type: text}`;
- `thinking: {type: disabled}` — одинаково для всех, чтобы sampling-параметры действовали;
- один endpoint `https://api.deepseek.com/chat/completions`;
- параллельный запуск, тайм-аут 120 с, без автоматических повторов.

## Метрики

`Stopwatch` запускается непосредственно перед `client.post` и останавливается сразу после получения полного HTTP body. Время включает сеть и генерацию, исключает разбор JSON и отрисовку. При HTTP/сетевой ошибке отдельно показано время до ошибки, а не время успешного ответа.

Input/output/total берутся из `usage.prompt_tokens`, `completion_tokens`, `total_tokens`. Cache hit — из `prompt_cache_hit_tokens` (или возвращаемого API `prompt_tokens_details.cached_tokens`). Никакого подсчёта токенов по символам/словам нет.

Тарифы USD за 1 млн токенов, проверены 06.09.2026 по официальной странице:

| Модель | Input без cache | Cached input | Output |
|---|---:|---:|---:|
| Flash / Vision, off-peak | 0.22 | 0.007 | 0.66 |
| Pro, off-peak | 0.66 | 0.022 | 1.98 |

Peak в будни 01:00–04:00 и 06:00–10:00 UTC: все ставки вдвое выше.
Формула: `((input − cached) × inputRate + cached × cachedRate + output × outputRate) / 1 000 000` с применением peak-множителя.
Это расчёт по опубликованному тарифу, не сумма из биллинга аккаунта. Если отсутствует usage/cache, API вернул другую модель или запрос находится около границы тарифных периодов (запас 1 минута), показывается N/A. Источник и дата зафиксированы; при изменении тарифов ставки нужно обновить.

| Модель | Время, с | Input | Output | Total | Cached | USD, off-peak | Завершение |
|---|---:|---:|---:|---:|---:|---:|---|

Стоимость независимо пересчитана десятичной арифметикой; input + output совпадает с total во всех трёх ответах.

Ручная оценка:

- **Flash:** сначала A,C,D,F / 34, затем замечает D,E,F,G / 35 и исправляет решение в тексте. Начальный пункт с набором остаётся неверным. Ответ многословный, превышает 250 слов и обрезан на 1600 output tokens; доказательство не завершено.
- **Vision:** A,C,D,F / 34 — допустимо, но неоптимально. Утверждение о полном переборе неверно, доказательство содержит противоречия. Ответ укладывается в лимит слов.
- **Pro:** A,C,D,F / 34 — тоже неоптимально. Проверка выбранного набора аккуратнее, но доказательство глобального максимума неверно; у перечисленных альтернатив есть ошибки в пользе. Ответ укладывается в лимит слов.

В этом запуске Vision быстрее и дешевле; Pro использует меньше output tokens; Flash расходует больше всех и достигает правильного решения только внутри незавершённого ответа. Более дорогая модель не гарантирует правильность. Ни один ответ полностью не удовлетворил заданию. Скорость зависит и от сети/нагрузки, цена — от длины ответа и cache hit. Один запуск не доказывает общий рейтинг моделей.
