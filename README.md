# Day 32 — Automated Code Review

Day 32 добавляет автоматическое ревью PR на локальном Mac runner через MCP,
RAG Day 31 и Ollama. Настройка: [Code Review](#day-32--automated-code-review).
Workflow: `.github/workflows/ai-review.yml`, общий механизм: `gateway/code_review.py`.
Ручной запуск того же механизма — комментарий `/review` в GitHub PR.

AI Advent — Flutter-чат с ассистентом разработчика. Команда `/help` отвечает
по документации собственного проекта и получает реальную Git-ветку через MCP.
Обычные сообщения остаются обычным чатом с локальной Ollama `qwen3:4b`.

## Структура проекта

- `lib/main.dart` — Flutter UI: URL Gateway, Bearer-токен, история, ввод `/help`.
- `lib/local_llm_client.dart` — HTTPS-клиент `POST /v1/chat`, таймаут 6 минут.
- `gateway/gateway.py` — авторизация, ограничения, очередь, обычный чат и `/help`.
- `gateway/developer_assistant.py` — выбор источников, RAG, MCP-клиент, проверка цитат.
- `server/developer_server.dart` — MCP-сервер, инструменты `get_current_branch` и `get_pr_changes`.
- `README.md` и `docs/**/*.md` — актуальная документация для RAG.
- `gateway/cloudflared.example.yml` — пример конфигурации HTTPS-туннеля.

Подробнее: [архитектура](docs/architecture.md), [RAG](docs/rag.md), [MCP](docs/mcp.md).

## Ручной запуск

Команды выполняются пользователем из корня существующего проекта.
Python 3.10+, Flutter SDK, Git, Ollama и при доступе с телефона `cloudflared`.

```sh
flutter pub get
ollama pull qwen3:4b
ollama pull embeddinggemma
```

Запустите установленное приложение Ollama либо `ollama serve` в отдельном
терминале, если сервер ещё не работает. Ollama слушает `127.0.0.1:11434`.
`embeddinggemma` нужна только для локальных embeddings RAG, ответы генерирует
`qwen3:4b`. Облачных LLM нет.

В отдельном терминале:

```sh
dart run server/developer_server.dart
```

MCP слушает `127.0.0.1:3000/mcp`. Корень проекта определяется по расположению
скрипта, а не по текущему каталогу терминала. Не публикуйте MCP наружу.

Создайте секрет и запустите Gateway в другом терминале:

```sh
python3 -c 'import secrets; print(secrets.token_urlsafe(32))'
export GATEWAY_TOKENS='YOUR_GENERATED_SECRET'
python3 gateway/gateway.py
```

Gateway слушает `127.0.0.1:8080`. Секрет — минимум 32 ASCII-символа.
Не сохраняйте его в git. Затем в отдельном терминале:

```sh
cloudflared tunnel --url http://127.0.0.1:8080
flutter run -d <DEVICE_ID>
```

Введите выданный HTTPS origin без пути и Bearer-токен в Flutter.
Для iPhone требуется настроенная подпись Xcode. Cloudflare передаёт запросы
на Gateway и может обрабатывать содержимое; Ollama и MCP доступны только локально.
Веб-клиент/CORS не реализованы. Для постоянного адреса можно использовать
`gateway/cloudflared.example.yml` с собственными hostname, UUID и credentials.

## Ограничения

HTTP API прежний: `POST /v1/chat`, JSON `{"messages":[{"role":"user","content":"/help Как устроен проект?"}]}`,
Bearer-авторизация. История хранится только в памяти Flutter. Для `/help`
используется текущий вопрос, предыдущие ответы не становятся источниками фактов.

6 запросов за 60 секунд на токен; до 24 чередующихся сообщений user/assistant;
тело до 32768 байт, история до 6000 UTF-8 байт. «Новый чат» очищает историю.
Одна активная генерация, три ожидающих; ожидание очереди до 160 секунд.
Ollama: `num_ctx=8192`, ответ до 512 токенов. RAG запрашивается лениво;
несколько последовательных локальных запросов могут занять время, туннель может
оборвать ожидание раньше клиента. Ошибки: 401, 400, 413, 429, 503, 502/504.
Обрезанные или невалидные ответы ассистента отклоняются.

## Day 32 — Automated Code Review

## Поток

PR → `pull_request_target` → выделенный self-hosted Mac → MCP
`get_pr_changes(base, head)` → Git merge-base + changed files + diff → существующий
Day 31 RAG → Ollama `qwen3:4b` → комментарий PR и artifact `review.md`.

`gateway/code_review.py` — общий механизм автоматического и ручного ревью.
Ручной запуск: отдельный комментарий `/review` в открытом PR от OWNER, MEMBER
или COLLABORATOR. Комментарии бота и прочий текст игнорируются. Flutter UI
для этой команды не нужен. Повторные комментарии создают новые запуски;
собственный результат не запускает ревью. Очередь последовательна для каждого
PR; запущенная генерация не прерывается. Перед публикацией повторно проверяются
base/head SHA: устаревший результат заменяется уведомлением.

## MCP и RAG

Workflow получает актуальные SHA через GitHub API, загружает оба commit через
Git fetch без checkout head. MCP принимает только полные SHA, вычисляет
`git merge-base base head`, затем `git diff ancestor head` (не рабочую копию).
Возвращает список всех изменённых путей, unified diff и разрешённые Git blobs
README, docs Markdown и исходников `lib/**/*.dart`, `server/**/*.dart`,
`gateway/**/*.py` из head. Symlink и executable blobs не индексируются.
Git вызывается без shell, external diff/textconv выключены.

Day 31 `split_document`, embeddings `embeddinggemma`, cosine ranking и top-3
переиспользованы через необязательный corpus в `retrieve`. Для каждого пакета
diff выполняется retrieval по имени файла и изменениям. Источники включают
документацию и исходный код head; это контекст, а не гарантированно полная
картина межфайловых зависимостей. Семантический поиск дополняется точным
поиском мест использования идентификаторов из изменённых строк в том же MCP
Git snapshot: определения, проверки и вызывающий код. На пакет передаются
до 2600 UTF-8 байт таких фрагментов и до 1200 байт semantic retrieval.
Фрагменты кода содержат путь и точную начальную строку. Индекс остаётся
в памяти, без базы и новых сервисов.

Модель возвращает JSON до трёх замечаний на пакет: bug, architecture,
improvement, строка либо null, краткое описание. Один проход модели на пакет; схема ответа ограничивает цитаты
изменёнными строками diff, а номера — добавленными строками. Неподтверждённая
цитата даёт незавершённый результат, а не молча удаляется из отчёта. Ответ собирается в текст по трём категориям. Пустые категории явно отмечаются, проблемы ради
заполнения не требуются. Номера принимаются только для добавленных строк
соответствующего файла; остальные замечания указывают файл без строки.
Удаления могут иметь замечания без номера новой строки. Результат — рекомендация
модели, а не доказательство отсутствия ошибок; тесты workflow не запускает.

## Предсказуемые ограничения

До LLM проверяются весь snapshot и разбиение: максимум 40 файлов, 48000 байт
diff, 32 пакета по 2400 UTF-8 байт, одна строка максимум 2400 байт.
RAG corpus: 64000 байт/файл, 256000 байт суммарно. Бинарный diff не анализируется.
Превышение, недоступный сервис, пустой корпус или невалидный/обрезанный JSON
дают комментарий **НЕ ЗАВЕРШЕНО**, artifact и failed job; частичные находки
не публикуются как полное ревью. Большой PR нужно разделить или проверить вручную.
Модель: num_ctx=8192, num_predict=512, temperature=0, think=false.
Ограничения намеренно консервативны для qwen3:4b.

## Настройка Mac и GitHub

1. Сначала внесите Day 32 в доверенную default/целевую ветку. Workflow и скрипты
   должны уже быть в base: первый PR, добавляющий сам механизм, ещё не сможет
   проверить себя новым механизмом.
2. Используйте приватный репозиторий с доверенными участниками. Fork PR
   автоматически не обслуживаются и вручную отклоняются. `pull_request_target`
   выбран для выполнения кода base, никогда head. На персональном Mac не
   подключайте этот runner к произвольным публичным PR. Для публичного проекта
   используйте изолированную машину и отдельную политику допуска.
3. На Mac установите Python >=3.10, Flutter/Dart согласно pubspec, Git, Ollama.
   Выполните сами `ollama pull qwen3:4b` и `ollama pull embeddinggemma`.
   Запустите Ollama на `127.0.0.1:11434`. Не публикуйте её порт наружу.
4. GitHub → Settings → Actions → Runners → New self-hosted runner → macOS.
   Выполните команды регистрации из GitHub, добавьте label `ai-review`,
   запустите runner как сервис по инструкции GitHub. Регистрационный токен
   вводится при настройке runner, не сохраняется в репозитории или LLM.
5. В Settings → Actions разрешите используемые actions и выдачу workflow
   прав contents:read, pull-requests:write, issues:write. Workflow использует
   встроенный краткоживущий `github.token`; PAT и дополнительные repository
   secrets не нужны. Возможные ограничения организации на запись должны быть
   разрешены администратором. GH_TOKEN передаётся только trusted Python driver;
   для Git fetch используется временная конфигурация без сохранения credentials.
6. Mac должен быть включён и доступен GitHub по исходящему HTTPS. PATH сервиса
   runner должен содержать flutter, dart, python3, git, nc. Один runner на Mac;
   порт 3000 свободен. Не держите Day 31 MCP на этом порту одновременно.
   Workflow сам запускает и завершает доверенный MCP, Ollama остаётся работающей.
   Не нужны Gateway, Cloudflare или Flutter-приложение.

PR-код, документация и ответы модели считаются недоверенными. Head не
checkout-ится, зависимости из head не устанавливаются, команды из diff не
выполняются. README/код отправляются только локальной Ollama. Переменные
окружения, GitHub event payload, токены и содержимое локальной `.env` не входят
в prompt. Из Git blobs читается только allowlist. PR с чувствительными путями
или распознанными ключами отклоняется до LLM. Это эвристический фильтр, поэтому
секреты нельзя коммитить даже в обычные исходники/документацию. На Mac runner
не храните production credentials; не устанавливайте ему лишние secrets.
