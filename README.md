# AI Advent — Day 9 · Compression истории

Agent автоматически отправляет **system + summary старых сообщений + recent messages + новый user**,
а при Compression OFF — system + полную историю + новый user. Дополнительных ключей не нужно:
используется существующий `DEEPSEEK_API_KEY` из ignored `.env`.

```sh
flutter run --dart-define-from-file=.env
```

## Политика

Константы в `AgentConfig`: `recentWindowSize = 4`, `compressionThreshold = 8`,
`summaryMaxTokens = 400`. Compression по умолчанию ON; переключатель сохраняется.
Перед chat request проверяется количество ещё не сжатых исторических сообщений,
без текущей user-реплики. Когда их не меньше 8, старый префикс сжимается, последние
4 сообщения сохраняются дословно. Сжатие не разрывает обычную пару user/assistant.
В нормальном диалоге первое сжатие происходит перед пятым запросом, затем перед седьмым,
девятым и т.д. Между сжатиями recent-буфер растёт; после ответа может содержать 6–8 сообщений.

Первый summary создаётся LLM из старого префикса. Следующие запросы summarization получают
только `existing_summary + messages_leaving_window`, а не всю историю с самого начала.
Внутренний prompt просит компактно сохранить имена, числа, факты, ограничения, решения,
предпочтения и открытые вопросы, учитывая новые исправления. Summary — до 180 слов,
API-лимит 400 output tokens. Используется та же DeepSeek Flash и sampling config.

Summary хранится отдельно от original messages. В chat request включается один system-блок
с summary и только сообщения после `compressedCount`; оригинальный сжатый префикс не дублируется.
При OFF summary не передаётся вообще. При возврате ON обработка продолжается от сохранённой границы.
Если summary пустой, обрезан или вызов завершился ошибкой, старый summary и граница остаются
неизменными, выводится предупреждение. Chat использует прежний summary и весь ещё не сжатый хвост;
следующая отправка снова попробует сжать его. Usage неуспешной попытки учитывается, если API его вернул.

## Persistence Day 7

Файл по-прежнему `Application Support/conversation.json`. Запись атомарная через `.tmp` и rename.
Новый JSON содержит `messages`, `summary`, `compressedCount`, режим, число сжатий, размер summary,
chat/summarization usage и последние input-метрики OFF/ON. Старый JSON-массив Day 7 читается автоматически.
Recent восстанавливается как суффикс original messages от сохранённой границы, без отдельной копии.
История для UI остаётся полной. Только `_context()` определяет, что реально отправится модели.
Старые сообщения не получают выдуманных token usage; накопительные метрики начинаются с Day 9.

Перед сетью user и состояние записываются на диск. После summary новое состояние сохраняется
до chat request; после ответа сохраняются ответ и счётчики. Очистка сбрасывает историю, summary
и usage. Ошибки диска показываются пользователю. Восстановление после штатного restart проверено;
аварийное завершение между получением HTTP-ответа и записью может потерять последние метрики.

## Метрики и UI

Переключатель ON/OFF, чат и раскрываемый debug-блок без dashboard:

- original/compressed/recent message count;
- текущий summary и число сжатий;
- context/input, response и total из настоящего API usage;
- chat input/output/total отдельно от summarization input/output/total;
- cumulative = chat total + summarization total;
- summary tokens — output tokens последнего успешного summary-вызова (не оценка его вклада
  в следующий input: там есть дополнительное оформление);
- последние измеренные context OFF/ON явно помечены как **разные запросы**. Это не вычисленный
  контрфактический размер одного запроса. Для честного сравнения ниже использованы два чистых сценария;
- при неизвестном usage показывается число таких вызовов, сумма отмечается как неполная.

Оценка Current message из Day 8 остаётся грубой оценкой только новой реплики; она не используется
для отчёта об экономии, выбора границы сжатия или подсчёта накопительного расхода.

## Реальный эксперимент 10.09.2026

Ручной сценарий: `dart run tool/run_day9.dart`. Он использует тот же Agent и API,
создаёт отдельные временные файлы, не меняет сохранённый чат приложения.
Десять одинаковых user prompts в обоих режимах, `temperature=0`, `maxTokens=250` для chat,
400 для summary. Ответы моделей могут отличаться, поскольку контекст после сжатия меняется.

Ранние факты: **Orion, зелёный, пятница, Ирина, 48000 рублей**. Затем восемь обсуждений
разделов интерфейса. Последний вопрос просит перечислить факты, не подставляя их значения.
Все промежуточные assistant messages получены реальными API-вызовами.

| Метрика | OFF | ON |
|---|---:|---:|
| Финальный context/input | 2196 | 1218 |
| Финальный response | 32 | 33 |
| Cumulative chat input | 11705 | 8323 |
| Cumulative chat output | 713 | 606 |
| Cumulative chat total | 12418 | 8929 |
| Summarization input | 0 | 2252 |
| Summarization output | 0 | 907 |
| Summarization total | 0 | 3159 |
| Итог, включая summarization | **12418** | **12088** |

Три успешных сжатия перед запросами 5, 7, 9. Размеры summary: 214, 298, 395 output tokens.
Их полная стоимость в токенах (input+output): 687, 1147, 1325.
У финального запроса ON было 12 сжатых сообщений и 7 оригинальных сообщений в API
(6 recent + текущий user); после ответа recent стал 8. Начальное сообщение с фактами
находилось только в summary, а не среди отправленных оригинальных сообщений.

Финальные ответы:

- OFF: «Проект Orion, основной цвет зелёный, релиз в пятницу, менеджер Ирина, бюджет 48 000 рублей.»
- ON: «Проект Orion, основной цвет зелёный, релиз в пятницу, менеджер Ирина, бюджет 48 000 ₽.»

Все пять фактов сохранены. Input финального запроса уменьшился на **44,5%**, но общий
расход с учётом сжатия уменьшился только на **330 токенов / 2,7%**. На более короткой
истории compression может быть дороже. Это наблюдение одного сценария, не обещание экономии
или сохранения всех деталей. Здесь сравниваются токены, а не денежные счета: cache и разные
ставки input/output также влияют на деньги.

Полные prompts, ответы, summary, usage и реально отправленные chat messages:
[docs/day9-results.json](docs/day9-results.json).

## Проверки

Ручной live-сценарий проверил дословное совпадение отправленного recent-суффикса с original history
на каждом ходе, отсутствие старого префикса в chat request и восстановление summary, границы,
истории и cumulative usage после пересоздания Agent на ходах 5 и 7 в обоих режимах.
Финальный `flutter analyze`: No issues found. Приложение собрано и запущено на iPhone 16e simulator; основной экран проверен по скриншоту, прежний сохранённый чат восстановился. API-сценарии выполнены через общий Agent из CLI, а не через UI-автоматизацию.
Новые automated tests не создавались, `flutter test` не запускался.

## Короткое видео

1. Показать Compression OFF, чистый чат и ранние пять фактов.
2. После нескольких сообщений спросить факты и показать context/input и общий расход.
3. Очистить чат, включить ON и повторить те же user prompts из `tool/run_day9.dart`.
4. После пятого запроса раскрыть debug: summary, compressed count, recent count и расход summary.
5. Перезапустить приложение, убедиться, что summary и история восстановились, продолжить диалог.
6. Задать финальный вопрос и сравнить факты и метрики. Для короткого ролика можно показать
   уже выполненный сценарий и таблицу отчёта: 2196 → 1218 input, но 12418 → 12088 всего.
