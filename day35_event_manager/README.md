# Day 35 — AI Event Manager

Самостоятельный локальный MVP: реальные мероприятия на ближайшие субботу и воскресенье → персонализация DeepSeek → 5–7 рекомендаций → Telegram. Не зависит от Flutter и серверов предыдущих дней. Python 3.11+ на macOS, только стандартная библиотека; база данных и дополнительные процессы не нужны.

## Настройка и запуск

```bash
cd day35_event_manager
cp .env.example .env
# Заполните .env в редакторе
python3 app.py
```

Откройте <http://127.0.0.1:8035>. Остановка — `Ctrl+C`. Не требуется устанавливать пакеты через pip. Если `python3 --version` ниже 3.11, установите современный Python с python.org. Сервер слушает только `127.0.0.1`.

| Переменная | Значение |
| --- | --- |
| `TICKETMASTER_API_KEY` | Consumer Key приложения Ticketmaster Discovery API |
| `DEEPSEEK_API_KEY` | API-ключ DeepSeek |
| `DEEPSEEK_MODEL` | Необязательно, по умолчанию `deepseek-chat` |
| `TELEGRAM_BOT_TOKEN` | Токен Telegram-бота, созданного через @BotFather |
| `TELEGRAM_CHAT_ID` | ID личного чата или группы; для группы может быть отрицательным |
| `PORT` | Необязательно, по умолчанию `8035` |

Ключи: [Ticketmaster Developer](https://developer.ticketmaster.com/), [DeepSeek](https://platform.deepseek.com/). Отправьте своему Telegram-боту `/start`, прежде чем отправлять сообщения в личный чат. ID чата можно получить через официальный Bot API `getUpdates` после сообщения боту; не передавайте токен сторонним сайтам. Приложение не использует polling или webhook, поэтому Telegram-кнопки обратной связи не предусмотрены: оценки ставятся в веб-интерфейсе.

`.env` читается только из этой папки; переменные окружения процесса имеют приоритет. Поддерживаются строки `KEY=value`, комментарии отдельной строкой и внешние кавычки. После изменения `.env` перезапустите сервис. `.env` и `data/` исключены из Git. Не публикуйте их: JSON содержит профиль, пожелания, отзывы и историю событий. Логи не записывают URL запросов, ключи и ответы с ошибками API.

## Как пользоваться

1. Укажите город латиницей, его **IANA часовой пояс**, интересы через запятую и дополнительные пожелания. Нажмите «Сохранить предпочтения». По умолчанию: Warsaw, Europe/Warsaw; теннис, кино, спорт, искусство, концерты.
2. Нажмите **«Найти мероприятия сейчас»**. Запуск использует сохранённый профиль и сразу отправляет результат в Telegram. Прогресс виден в журнале, страница обновляет статус каждые 3 секунды.
3. В рекомендациях нажимайте «Нравится» или «Не подходит». Эти оценки с названием, категорией и площадкой учитываются в следующем AI-анализе; «Сбросить» удаляет оценку. Это предпочтения, а не строгие фильтры.
4. Все полученные события находятся в раскрывающемся блоке. В карточках сохраняются данные источника: название, точная дата и время, площадка, адрес при наличии, описание и ссылка. Если отдельного описания нет, показываются категории источника или соответствующее уведомление.

Профиль и отзывы сохраняются атомарно в `data/state.json`. Одновременно выполняется одна подборка; второй процесс из той же папки блокируется файловой блокировкой. Профиль можно редактировать во время поиска: текущий запуск использует снимок настроек, следующий — обновлённые настройки.

## Реальные события и границы покрытия

Источник — [Ticketmaster Discovery API v2](https://developer.ticketmaster.com/products-and-docs/apis/discovery-api/v2/), endpoint `/discovery/v2/events.json`. Запрос содержит город и точный диапазон UTC; время для пользователя переводится в часовой пояс города через `zoneinfo` с учётом летнего времени. Часовой пояс задаётся отдельно: встроенного геокодирования нет, поэтому при смене города проверьте его вручную.

Ближайшие выходные — суббота и воскресенье. В субботу выбирается остаток текущих выходных, в воскресенье — оставшееся воскресенье. События без подтверждённого времени, отменённые, перенесённые, прошедшие, без площадки или ссылки исключаются. Проверка времени повторяется после AI-анализа и перед отправкой каждого сообщения. Дубли исключаются по ID и по сочетанию названия, времени и площадки.

Обрабатываются до 500 событий в порядке даты, до 5 страниц по 100. Для ограничения стоимости и размера контекста AI получает первые 100; интерфейс предупреждает об обоих ограничениях. Большой город может потребовать более узких интересов или другого источника в будущей версии.

**Ticketmaster не является полной афишей города.** Особенно ограничено покрытие киносеансов, небольших выставок и любительского тенниса. Сервис не заполняет пробелы вымышленными событиями. Если источник не вернул подходящие достоверные события, это отражается в журнале и статусе, AI и Telegram не вызываются. Если событий меньше пяти, отправляются доступные. Ошибка API отображается как ошибка, а не как отсутствие событий.

## Участие AI

DeepSeek получает только события из API, профиль и до 60 последних отзывов. Возвращает JSON с ID выбранных событий, объяснением соответствия интересам и переводом названия и краткого описания на русский. Сервер проверяет, что ID существуют, не повторяются, перевод и причины непустые и число рекомендаций соответствует диапазону 5–7 (или числу доступных событий, если их меньше). Исходные факты берутся из источника; дата, площадка, адрес и ссылка не переводятся. Модель получает инструкцию сохранять имена артистов, названия групп и бренды в оригинале и не добавлять факты.

В рекомендациях на сайте и в Telegram используются русские названия и описания. На сайте исходный текст доступен в блоке «Оригинал из источника». В списке всех найденных событий перевод появляется у событий, вошедших в рекомендации; остальные показываются на языке источника. Перевод и причина рекомендации генерируются моделью и могут содержать ошибки. После обновления сервиса перезапустите его и выполните новый поиск: старые сохранённые карточки автоматически не переводятся. Версия кеша обновлена, поэтому прежний результат без перевода не используется повторно. Русская версия считается изменённой подборкой и может быть заново отправлена в Telegram.

При неизменных событиях, профиле и отзывах повторно используется последний сохранённый AI-результат. При некорректном ответе AI автоматической подмены эвристиками нет: отправка останавливается, причина показывается в интерфейсе. В DeepSeek передаются город, пожелания и отзывы; не вводите в пожелания секретные данные.

## Telegram и повторные отправки

Отдельное сообщение для каждой рекомендации содержит период, часовой пояс, дату, место, описание, причину и ссылку. Используется обычный текст, без интерпретации HTML из источника. На диске сохраняются хеш подборки и квитанция каждого успешно отправленного сообщения. Повтор неизменной подборки пропускается, в том числе после перезапуска. Если часть сообщений отправлена, повторный ручной поиск при неизменных данных продолжит с отсутствующих сообщений без нового LLM-вызова. При изменении событий, профиля или отзывов результат может стать новой подборкой.

Как у любого клиента Bot API, есть небольшой неопределённый случай: Telegram принял сообщение, но соединение оборвалось до ответа или процесс завершился до сохранения квитанции. Тогда повтор может создать дубль; строгая гарантия exactly-once через `sendMessage` недоступна. Автоматического повтора сетевых ошибок нет; журнал и статус показывают, что запуск не завершён. Не удаляйте `data/state.json`, если хотите сохранять историю отправок.

## Еженедельный запуск на Mac

В разделе «Расписание отправки» выберите любой день недели и время с точностью до минуты, затем нажмите «Сохранить расписание». Время относится к часовому поясу сохранённого города. Настройки сохраняются в JSON и действуют без перезапуска. Для существующего профиля при первом обновлении устанавливается прежнее значение: четверг, 19:00; остальные настройки и ключи сохраняются.

Планировщик встроен в процесс и проверяет время каждые 30 секунд. Квитанция запланированной попытки сохраняется до поиска: повторного автоматического запуска по тому же расписанию в тот же день не будет даже после перезапуска. При ошибке исправьте настройки и запустите вручную. Изменение города, часового пояса, дня или времени создаёт отдельный ключ расписания. Защита от повторной отправки неизменной подборки продолжает действовать.

Mac должен быть включён, иметь интернет, а `python3 app.py` — продолжать работать. Можно держать процесс в Terminal или вручную настроить macOS LaunchAgent с `RunAtLoad` и `KeepAlive`, абсолютным путём к Python и `app.py`. VPS не нужен. Для временной демонстрации без сна можно вручную запустить `caffeinate -i python3 app.py` из папки проекта.

При запуске или пробуждении **в выбранный день после выбранного времени** пропущенная попытка выполняется в ближайшие 30 секунд. Это также относится к сохранению нового расписания: если время сегодня уже прошло, поиск начнётся сразу на ближайшем тике. Пропуски прошлых дней не догоняются. Если Mac спит весь выбранный день после времени отправки, отправки не будет. В интерфейсе показывается следующий запуск. Смена часового пояса компьютера не влияет на расписание профиля. При весеннем переходе на летнее время несуществующее местное время сдвигается вперёд на величину перехода; при осеннем повторе часа попытка выполняется один раз.

## Ручная проверка после настройки

Эти действия вызывают реальные API и могут расходовать средства DeepSeek. В ходе реализации они не выполнялись.

- **Поиск:** запустите сервис, сохраните Warsaw / Europe/Warsaw и нажмите ручной запуск. Проверьте журнал `поиск → AI-анализ → рекомендации → Telegram`, выходные, дату/место по ссылке источника. Пустой результат допустим и не заменяется выдумкой. Проверьте также некорректный API-ключ: ожидается явная ошибка.
- **Персонализация:** оцените несколько рекомендаций, измените пожелания, повторите поиск. Проверьте причины и сохранение профиля/оценок после перезапуска.
- **Telegram:** после `/start` ожидайте по одному сообщению на рекомендацию. При неверном chat ID карточки остаются в интерфейсе с ошибкой отправки. Исправьте `.env`, перезапустите и повторите поиск. Если данные не изменились, повторная отправка уже доставленных сообщений пропускается; повторный запуск неизменной подборки покажет соответствующий статус.
- **Расписание:** выберите в веб-интерфейсе сегодняшний день и время на несколько минут вперёд, сохраните расписание и проверьте «Следующий запуск». Оставьте сервис работающим до выбранного времени. В JSON текущего запуска появится `trigger: schedule`, в журнале — весь поток. Перезапуск в тот же день не должен инициировать вторую попытку по неизменному расписанию. После проверки сохраните желаемый день и время. Для быстрой демонстрации самого потока используйте ручную кнопку; она вызывает ту же функцию обработки. Перевод системных часов для проверки не требуется.
- **Логи:** журнал в интерфейсе хранит последние 150 записей; файл `data/events.log` содержит полный журнал процесса. Секреты для проверки присылать не нужно.
