# MCP и текущая Git-ветка

`server/developer_server.dart` использует mcp_dart 2.4.2 из Day 20.
StreamableMcpServer слушает `127.0.0.1:3000/mcp` с JSON-ответами.
Day 31: `get_current_branch`, без аргументов и без записи файлов.
Day 32: `get_pr_changes` получает base/head SHA и возвращает PR snapshot;
подробности и ограничения — [Code Review](../README.md#day-32--automated-code-review).

На каждом вызове инструмент выполняет `git -C <корень проекта> symbolic-ref
--quiet --short HEAD` через Process.run, без shell. Корень определяется по
расположению скрипта. Имя не хранится в настройках и не кешируется.
Возвращается structuredContent с branch и detached. Detached HEAD означает,
что текущей ветки нет; ошибка Git возвращает MCP isError.

Python Gateway выполняет MCP lifecycle: initialize, notifications/initialized,
tools/list с пагинацией, затем tools/call. Проверяются наличие инструмента,
ошибки протокола и структура результата. Сессия закрывается DELETE.
Сервер не нужно публиковать через туннель: к нему обращается только Gateway.

Результат MCP передаётся локальной qwen3:4b. Ответ должен цитировать MCP;
Gateway дополнительно выводит фактическое значение branch отдельной строкой.
Источник: `mcp://developer/get_current_branch`. Если MCP недоступен,
Gateway возвращает ошибку, документация не используется как замена живой ветки.

## Day 33: пользователи и обращения

Тот же сервер предоставляет get_ticket({id: integer}) и get_user({id: integer}).
Читаются data/tickets.json и data/users.json при каждом вызове; только чтение.
Gateway сам берёт user_id из тикета, а не из ответа модели. Источники:
`mcp://support/get_ticket/42`, `mcp://support/get_user/101`.

## Day 34: Project File Assistant

`/files <цель>` использует `gateway/file_assistant.py`: qwen3:4b выбирает
инструмент и его аргументы двумя короткими ответами по JSON schema. Gateway проверяет название и аргументы,
вызывает существующий `McpClient` (initialize → tools/list → tools/call → DELETE)
и возвращает результат модели. Нет сценарного роутинга по словам RAG/MCP.
Доступно до 24 шагов, до 8 прочитанных файлов и 4 поисков, контекст 32768
токенов, до 85KB результатов инструментов и 8 минут на анализ после очереди.
Перед завершением или diff нужны минимум три файла, включая два исходника;
перед diff также читается целевой файл. После первой документации приоритет
получают исходники реализации.
Это ограничение не гарантирует полноту семантического анализа маленькой модели.

Инструменты того же Dart MCP-сервера:

- `list_files({query})`: подстрока пути, пустая строка — список;
- `search_text({query})`: буквальный поиск без учёта регистра по нескольким файлам,
  пути, номера строк и фрагменты; максимум 100 результатов / 3000 файлов,
  флаг `truncated` требует сузить поиск; list_files также возвращает ограниченный
  каталог безопасных путей в `catalog`;
- `read_file({path})`: UTF-8 содержимое и хеш исходной версии;
- `get_diff({path, content})`: полная замена текста, unified diff и хеш исходника,
  без записи;
- `write_file({path, content, expected?, approval?})`: без approval возвращает
  только preview; сохраняет файл лишь с подписанным подтверждением Gateway.

Модель предлагает короткую замену `old_text` → `new_text` для get_diff/write_file.
Gateway проверяет точное единственное совпадение в прочитанном оригинале, собирает
полное содержимое и вызывает MCP. Подпись и исходный хеш модель не задаёт.

Файловые операции реализует `server/file_tools.py`; Dart запускает только этот
фиксированный Python-скрипт без shell, параметры идут JSON через stdin.
Корень определяется расположением скрипта. Допускаются текстовые расширения,
существующие родительские каталоги, файлы до 64 KB, без удаления/переименования.
Абсолютные пути, `..`, скрытые компоненты, `.git`, `.env`, имена с признаками
секретов/ключей, бинарные файлы, hard links и symlinks запрещены. Каждый компонент
пути открывается через `dir_fd` и `O_NOFOLLOW`; обход дерева не следует symlinks.

Gateway хранит предложение в памяти 30 минут, привязывает его к Bearer identity.
Flutter опрашивает `/v1/files` и показывает найденные файлы, вызовы, diff,
«Подтвердить запись» и «Отменить». Только отдельный authenticated approve-запрос
создаёт HMAC для точных path/content/expected. Для Gateway и MCP необходим один
`FILE_APPROVAL_SECRET` (минимум 32 символа), не передаваемый модели/Flutter.
Перед записью повторно проверяется исходная версия; устаревший diff отклоняется.
Подтверждение одноразовое. Отмена не пишет файлы. Один diff — один файл; для
следующего изменения отправьте новый `/files` запрос после проверки результата.
Если текст совпадает, записи и предложения нет. Повторный запуск снова исследует
файлы; отсутствие бессмысленных семантических правок зависит также от модели и
проверки diff пользователем. Память заданий ограничена, предложения теряются
при перезапуске. Закрытие Flutter не останавливает анализ, но без approve записи нет.

Не запускайте параллельно внешние процессы, перемещающие каталоги проекта во
время записи. Проверка версии обнаруживает изменения между preview и approve;
это не транзакционная файловая система для конкурентных внешних редакторов.
