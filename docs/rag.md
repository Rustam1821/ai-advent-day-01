# Как реализован RAG

## Документы и индекс

RAG читает `README.md` и все Markdown-файлы `docs/**/*.md` из корня проекта
на Mac. Символические ссылки на файлы исключаются. Индекс лениво создаётся
при первом вопросе к документации; SHA-256 содержимого и путей сравнивается
при каждом запросе. При изменении документов индекс перестраивается.
Индекс хранится только в памяти Gateway, после перезапуска строится снова.

StructureAwareChunker из Day 25 адаптирован в `split_document`: иерархия
Markdown-заголовков, учёт fenced code blocks, упаковка по абзацам, chunks до
1200 символов. Фрагменты только с заголовком исключаются. Метаданные: id, source, section, line и text. line — начало
раздела, а не точная строка цитаты внутри длинного раздела.

## Поиск и генерация ответа

Локальная Ollama `/api/embed` с `embeddinggemma` создаёт 768-мерные vectors
пакетами по 8. Запрос получает embedding той же модели. Cosine similarity
ранжирует chunks, берутся до 3 с similarity >= 0.30. Порог предварительный,
не откалиброван на текущем корпусе. Старый порог 0.45 из Rust-корпуса не перенесён.
При отсутствии релевантных chunks возвращается сообщение о недостатке контекста.

qwen3:4b получает текущий вопрос и найденные SOURCES, возвращает JSON answer
и citations с id/quote. Валидация проверяет, что id существует и quote — непустая
дословная подстрока text после нормализации пробелов и переносов строк. Неизвестные ссылки, неверные цитаты и обрезанный JSON
отклоняются. Источники добавляются Gateway как Markdown-ссылки `файл#Lстрока`
и цитаты. Документы трактуются как справочные данные, а не инструкции.

Используются только локальные модели: embeddinggemma для retrieval, qwen3:4b
для маршрутизации и ответа. Сохранённого индекса, БД, reranker и query rewrite нет.
